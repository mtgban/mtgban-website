Loading cards into MTGBAN from anywhere

This is the documentation for the card list handoff: the way another site, app or tool loads a list of cards into MTGBAN for whoever is using it. The cards land in the Uploader, priced against every store MTGBAN follows, in the reader's own session - nobody has to export a file and upload it by hand.

Use it to add a "Price it on MTGBAN" button to a storefront, a collection tracker, a deck builder, or anything else that holds a card list. To price a list yourself, paste or upload it at /upload - the formats below are the same ones that page takes.

Who can hand a list over

{{if .HandoffOrigins}}A list is taken from {{range $i, $origin := .HandoffOrigins}}{{if $i}}, {{end}}{{$origin}}{{end}}, and from nowhere else.{{else}}No site is currently allowed to hand a list over.{{end}} A sender is allowed by its origin, since a list is priced the moment it arrives. To hand lists over from your own site, ask on Discord to have its origin added.

The reader needs an MTGBAN account whose tier includes the Uploader. Anyone else is told so on this page, and no list is taken from them.

Handing a list over

Open this page with window.open from the page that holds the list, then send the list with postMessage. A plain form POST to /upload from another site would arrive without the reader's session; a page opened like this has it, and posts the list from here.

Once it is listening, this page announces itself to the window that opened it, then waits for as long as it takes. It takes one list and no more, and it listens only to the window that opened it, and only to a message from an allowed origin. 

// the sender opens this page, and sends the list once it is listening
const ban = window.open("https://mtgban.com/upload/handoff");
window.addEventListener("message", (event) => {
  if (event.source === ban && event.data.type === "mtgban-handoff-ready") {
    ban.postMessage(list, event.origin);
  }
});

// this page, once it is listening
{ type: "mtgban-handoff-ready" }

// the list, in reply - either as text…
{ type: "mtgban-handoff-rows",
  text: "4 Rift Bolt\n1 Lightning Bolt (2ED) *F*\n",
  rows: 2,
  source: "https://cards.example/lists/42" }

// …or the same cards, already resolved
{ type: "mtgban-handoff-rows",
  cards: [
    { id: "6f4b4e4a-…", quantity: 2, condition: "NM", foil: false },
    { name: "Rift Bolt", edition: "TSP", number: "148", quantity: 1 }
  ],
  source: "https://cards.example/lists/42" }

text is anything described below - a CSV, a spreadsheet's worth of tab separated columns, a decklist. It is also accepted as csv.

cards is for a sender that knows its cards already and should not have to write a CSV to say so. Each entry names any of the fields below; the page writes them into the columns described further down, so the two shapes are read by exactly the same parser at the far end.

FieldWhat it says
idthe printing's uuid, which settles it outright
namethe card's name, where there is no id
editionthe set it is in
numberits collector number, or another variant
foiltrue or false
conditiona grade, in either spelling
quantityhow many, as a number
pricewhat they were paid for, shown beside the results
notesanything to carry through; a URL here becomes a link

An entry naming neither an id nor a name is dropped rather than sent as a blank line. rows is how many cards are on the way, shown while the upload runs; a cards list counts itself and does not need it. source is the page the list was read from, kept only when it belongs to the origin that sent the message; the results are headed with the sender's name and link back to it.

What a list looks like

Comma or tab separated text, with a header row naming the columns. Their order does not matter, and columns nothing recognises are ignored rather than refused. Matching is on substrings and case is ignored, so Card Name, name and Product Name all reach the same field.

FieldHeaders that reach it
Card nameanything with name in it, or card
Editionedition, set, expansion
Number or variantnumber, variant, variation, version, comment
Finishfoil, printing, finish, f/nf
Conditionanything with condition in it
Quantityquantity, qty, stock, count, have
Priceprice, low
Notesnotes, data - kept and shown, trimmed at 1024 characters

Naming the printing outright

A name and an edition identify most cards, but not all of them: a card printed twice in one set is told apart by its collector number, and some are not told apart by wording at all. An identifier settles it, and is tried before any of the columns above.

IdentifierHeaders that reach it
MTGJSON / Scryfall uuiduuid, id, key, scryfall id, mtgjson id
TCGplayer producttcgplayer product id
TCGplayer SKUtcgplayer id - carries the condition and finish too
Cardmarket productcardmarket id, mcm id, mkm id

A Cardmarket id names a product rather than a printing, so it is used only where nothing better answered, and only where one printing answers to it.

What the values may say

  • Condition is one of five grades - NM, SP, MP, HP, PO - written either way: NM and Near Mint both land on NM, as do Lightly Played and Excellent on SP, Moderately Played and Very Good on MP, Heavily Played and Good on HP, and Poor and Damaged on PO. A row with no condition is priced as NM.
  • Finish takes yes/no, true/false, 1, x, or a word containing foil. Anything naming non-foil is not one. An etched printing is named in the variant column instead.
  • Quantity is a whole number, with or without a trailing x. A row at zero is skipped, and rows for the same printing in the same condition are added together.

A list with no header at all

One column and no header is read as a decklist, the way it would be written out by hand: 

4 Rift Bolt
4x Rift Bolt (TSP)
1 Lightning Bolt (2ED) *F*
10 Swamp <462> [CLB]

The set goes in brackets, the collector number in angle brackets, and *F* or *E* on the end asks for the foil or etched printing. Without an edition the most recent printing is used.
